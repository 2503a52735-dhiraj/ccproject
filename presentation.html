PROJECT BACKGROUND

Introduction & Motivation

💡 The Edge-Trigger Paradigm
  • Traditional IoT devices continuously poll servers or maintain open TCP sockets, draining battery power and wasting cloud bandwidth.
  • The Smart Dash Button adopts an Event-Driven Architecture (EDA): the device remains completely idle until physically pressed.
  • A single push triggers an instant interrupt, establishes secure Wi-Fi, dispatches a cloud webhook, and immediately returns to sleep.
  • Massively reduces operational costs and maximizes hardware lifespan.
🌍 Real-World Applications
  • Industrial Smart Factory: Single-click machine emergency stops, hazard notifications, and maintenance logs.
  • Healthcare: Patient bedside nurse-call button with instantaneous cloud alerts.
  • Supply Chain & Logistics: Rapid one-touch inventory restocking (Amazon Dash model).
  • Smart Home Automation: One-tap security lockdown or scene activation without opening an app.

ENGINEERING CHALLENGES

Problem Statement & Objectives

⚠️ Core Challenges
  • Floating Pin State: Unbiased digital inputs pick up electromagnetic noise, firing random phantom triggers.
  • Mechanical Contact Bounce: Metal switch contacts oscillate for milliseconds, creating 5–10 duplicate triggers per push.
  • Insecure Transmissions: Cleartext HTTP packets over Wi-Fi expose IoT devices to interception and spoofing.
  • Dedicated Server Waste: Running full VMs 24/7 for sporadic button events is financially and computationally inefficient.
🎯 Project Objectives
  • Eliminate external resistors by utilizing the internal 10kΩ INPUT_PULLUP resistor on NodeMCU D2.
  • Implement a reliable 500ms software debounce filter to suppress electrical bouncing.
  • Establish TLS encrypted connections over Wi-Fi on port 443 via WiFiClientSecure.
  • Deploy a serverless webhook receiver and real-time verification dashboard.

3-TIER CLOUD MODEL

End-to-End System Architecture

1️⃣ Edge Layer
  • ESP8266 NodeMCU (160 MHz)
  • Physical Pushbutton on Pin D2 (GPIO 4)
  • Internal 10kΩ Pull-Up Resistor
  • Active Low Trigger (D2 → GND)
  • 500ms Debounce Delay Filter
2️⃣ Transport Layer
  • Wi-Fi 802.11 b/g/n Client
  • TLS 1.3 Transport Layer Security
  • WiFiClientSecure on Port 443
  • Structured JSON Payload
  • Zero-socket persistence on completion
3️⃣ Cloud Layer
  • Serverless Cloud Webhook
  • Auto-scales instantly from zero
  • Responds with HTTP 200 OK
  • Downstream database / notification trigger
  • Live Telemetry Web Dashboard

CIRCUIT DESIGN

Hardware Specs & Schematic Logic

🔌 NodeMCU ESP8266 Specs
  • CPU: Tensilica Xtensa L106 32-bit RISC running up to 160 MHz.
  • Memory: 64 KB Instruction RAM, 96 KB Data RAM, 4 MB SPI Flash.
  • Wi-Fi: Integrated 802.11 b/g/n baseband with PCB trace antenna.
  • Pin Assignment: Pin D2 corresponds directly to GPIO 4.
  • Power: 3.3V logic level powered through on-board micro-USB regulator.
⚡ Pull-Up Circuit Schematic
  • One leg of the pushbutton connects to Pin D2.
  • Opposite diagonal leg connects directly to GND.
  • Default State (Released): Internal pull-up holds D2 at 3.3V (HIGH).
  • Pressed State: Closing the button shorts D2 to GND, reading 0V (LOW).
  • Short Circuit Elimination: Removed the 3V3 power rail bypass from legacy diagrams, protecting the NodeMCU voltage regulator.

CLOUD SERVICES

Serverless Cloud Webhook Processing

☁️ Serverless Computing Benefits
  • Zero Idle Cost: Serverless workers (Cloudflare Workers / AWS Lambda) sleep until an incoming webhook packet arrives.
  • Instant Auto-Scaling: Handles single button pushes or 50,000 simultaneous pulses with zero configuration.
  • Global Edge Proximity: Dispatches to the nearest cloud edge node, reducing network latency.
📦 JSON Payload & Handshake
  • HTTP Method: POST / HTTP/1.1 with TLS encryption.
  • JSON Payload: {"message": "Hello from physical trigger button!", "pin": "D2", "device": "NodeMCU"}
  • Response: Returns HTTP 200 OK with {"status": "success", "received": true}.
